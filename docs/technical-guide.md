# 技术导览

[返回项目与截图](../README.md)

建议依次阅读：流式对话 → 编辑与保存 → 笔记整理 Agent → 数据保护与部署。

## 流式对话与取消

前端通过 fetch POST、ReadableStream 和增量 TextDecoder 接收 SSE，缓存未完整到达的行并识别完成标记，处理跨分包内容、超时和用户取消。连接中断与正常完成分别处理，取消操作向上游传递，避免界面停止后仍持续生成。

## 编辑器选区与保存一致性

润色以用户选区和上下文为输入，保留选区位置，经确认后替换对应内容；原内容发生变化时阻止直接覆盖，避免误发全文或重复插入段落。

笔记采用防抖、串行保存与提交快照，区分已提交内容和当前草稿，避免旧请求返回后覆盖新输入。加载过程与编辑过程分开处理，防止回填内容触发错误保存。

## 笔记整理 Agent

模型在限定工具范围内检索和读取当前用户笔记，按需组织资料，输出带来源引用的可编辑草稿。工具调用设置轮次与读取范围限制，服务端检查用户归属和引用有效性。

生成草稿与保存笔记分为两个步骤：用户编辑并明确确认后，系统创建新笔记，保留原笔记。保存通过用户绑定的草稿凭证、数据库事务及唯一回执处理重复提交。

## 用户数据与调用成本

服务端按资源归属检查笔记、会话等访问请求，富文本内容经过清洗。退出登录时清理页面状态并取消进行中的任务与语音操作，减少账号切换时的数据残留。

调用额度、共享预算与并发限制共同约束模型使用；额度预留结合数据库事务及条件更新，处理同时请求和失败释放，界面提供额度与异常反馈。

## 多模态与部署

语音识别通过 WebSocket 接入，朗读支持暂停与继续，生成图片保存到持久化存储。应用部署于 Railway，数据库与上传文件配有手动备份及隔离恢复流程。

语音识别的检查使用合成音频；实际体验随模型服务、网络和设备环境变化。本展示仓库不提供在线调用入口，浏览截图无需登录或消耗模型额度。
